
项目任务：开发 Inphic IN9 升级版 macOS 原生宏配置工具
一、项目目标
你是一名资深 macOS 原生应用工程师、USB HID 协议逆向工程师和 Swift 系统开发工程师。
请在当前工作区中开发一个真正可用的 macOS 原生应用，项目暂定名为：
InphicMouse for macOS
目标硬件：英菲克 Inphic IN9 升级版三模鼠标。
目标设备：Mac mini M4，Apple Silicon，macOS。
核心目标：在 macOS 上直接通过 USB HID 协议与 IN9 升级版通信，实现鼠标宏的创建、编辑、管理、绑定和写入，不再依赖 Windows 原厂配置软件。

* 可以独立分发的 .dmg。
* 完整的源代码。
* 自动化协议单元测试。
* 中文使用说明和开发文档。
这是一个真实硬件控制项目，不是 UI Demo。硬件通信和宏写入是最高优先级。

四、硬件协议要求
4.1 设备识别
首先识别 IN9 升级版设备。
上游项目记录的设备信息：
* 有线 USB VID：0x248A
* 2.4G 接收器 VID：0x249A
* IC 类型：0x11
* 目标连接方式：优先有线 USB，其次 2.4G。
以上 VID 是参考信息，不代表可以忽略 PID、接口号和 Usage Page。
必须从上游协议文档中确认完整设备匹配条件。
不要将普通鼠标 HID 接口误识别为配置接口。
必须能够：
* 枚举 HID 设备。
* 识别目标鼠标。
* 显示设备名称、VID、PID、接口和连接状态。
* 连接与断开。
* 监听鼠标插拔。
* 避免重复打开设备。
* 避免误操作其他鼠标。
如果存在多个匹配设备，必须提供明确的设备选择机制。
4.2 HID 通信协议
根据上游项目的 hid-protocol.md 实现。
已知协议信息：
固定通信帧为 33 字节：
* Byte 0：Report ID
* Byte 1：命令码
* Byte 2：0x00
* Byte 3：0x01
* Byte 4：载荷长度
* Byte 5-31：载荷
* Byte 32：校验和
校验和：
sum(buf[5..31]) & 0xFF
已知命令码：
命令   功能
0x02   回报率
0x03   DPI
0x04   DPI 颜色
0x05   灯光
0x06   传感器
0x07   休眠
0x08   宏内容
0x09   按键映射
0x0C-0x0E   配置复位
0x10-0x17   读取配置
0x20   无线固件相关
注意： 以上是协议研究的起点。具体请求帧、响应帧、载荷长度、ACK 规则、超时和重试规则必须以完整协议文档及源码为准。
禁止只根据 README 摘要实现协议。
4.3 通信安全
必须实现：
* 串行化设备读写操作。
* 请求超时。
* ACK 校验。
* 错误码与异常处理。
* 必要的重试机制。
* 设备断开时取消未完成请求。
* 写入后读回验证。
* 日志记录原始 HID 数据帧。
所有原始数据日志使用十六进制格式。
日志必须支持导出，方便后续协议分析。
禁止在通信失败时无限重试。
禁止把写入成功等同于 ACK 成功，必须区分：
1. 发送成功。
2. 收到 ACK。
3. 读回成功。
4. 实际宏执行成功。
五、宏功能：本项目的核心
本次 MVP 的最高优先级是宏功能。
5.1 宏数据模型
参考上游项目的宏数据模型和 MacroCodec.cs。
原厂 SQLite 数据库中已知的宏事件类型：
类型   含义
1   延时
2   键盘按下
3   键盘松开
4   鼠标按下
5   鼠标松开
键盘值使用 Windows VK 编码，鼠标按键使用按钮位编码，延时单位为毫秒。
上游项目已记录：
* 0x08 为宏上传命令。
* 每个宏动作编码为 4 字节。
* 数据格式为 [动作类型, 延时低字节, 延时高字节, 键值]。
* 宏数据经过分帧上传。
* 相关格式已经通过官方 USB 抓包校准。
必须进一步阅读 MacroCodec.cs，确认分帧、槽位、长度、结束标记、边界和校验规则。
不能只实现单帧上传。
5.2 宏编辑器
宏编辑器至少支持：
1. 创建宏。
2. 删除宏。
3. 重命名宏。
4. 复制宏。
5. 调整宏顺序。
6. 编辑宏事件。
7. 删除宏事件。
8. 插入键盘按下事件。
9. 插入键盘松开事件。
10. 插入鼠标按下事件。
11. 插入鼠标松开事件。
12. 插入延时事件。
13. 修改事件延时时间。
14. 上下移动事件。
15. 连续录制键盘和鼠标动作。
16. 停止录制。
17. 设置宏循环方式（仅限协议实际支持的模式）。
18. 保存宏到本地。
19. 从本地导入宏。
20. 将宏导出为 JSON。
21. 将宏写入鼠标。
事件列表应清晰展示：
序号   事件   操作   延时
1   键盘   按下 A   0ms
2   键盘   松开 A   50ms
3   鼠标   按下左键   100ms
4   鼠标   松开左键   50ms
以上仅为 UI 表现示例，实际数据编码必须遵循设备协议。
5.3 宏录制
实现真正的本地输入事件录制。
在 macOS 上研究并采用适合的输入事件监听方案，例如 CGEventTap。
注意：
* macOS 辅助功能权限。
* 输入监控权限。
* 用户明确授权。
* 录制状态提示。
* 开始和停止快捷操作。
* 录制期间避免将本软件自身操作错误录入宏。
* 处理按键按下和释放事件。
* 处理连续按键。
* 处理鼠标按键。
* 计算事件间隔并转换成毫秒延时。
如果用户没有授予权限，必须提供明确的系统设置引导，不能静默失败。
录制功能不得偷偷收集或上传用户输入。
5.4 宏执行与板载存储
这是必须重点验证的部分。
区分：
* 本地保存宏。
* 将宏上传到鼠标。
* 将宏绑定到鼠标物理按键。
* 鼠标固件执行宏。
不能把这四个概念混为一谈。
首先研究上游项目的宏上传和按键映射实现，确认：
* 宏槽位数量。
* 宏槽位与物理按键的对应关系。
* 宏数据是否写入鼠标内部存储。
* 是否存在循环模式。
* 是否支持宏执行与取消。
* 是否需要额外的按键映射命令。
完成上传后执行读回验证（如果设备协议支持）。
最终必须通过实际按键触发宏，验证鼠标是否能独立执行宏。
